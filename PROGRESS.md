# AppFleet — ход разработки

## Этап 1 — основание проекта

**Реализовано:** Git-репозиторий, Java 21/JavaFX Gradle-конфигурация, зафиксированные версии зависимостей, базовая точка входа, ротация технических логов и утверждённая структура проекта.

**Осталось:** доменная логика, GitHub REST-клиент, хранилище, безопасные операции установки, JavaFX-интерфейс, self-update, Inno Setup, CI и полный набор тестов.

**Проверки:** Java/Javac 21 x64 и Inno Setup 6 доступны локально; Gradle 8.14.3 доступен в кэше. Gradle Wrapper создан; `./gradlew.bat test` успешно завершилась (пока без тест-классов); `git diff --check` без замечаний.

## Этап 2 — домен, GitHub и сохранение состояния

**Реализовано:** строгая SemVer-логика; безопасная нормализация разрешённых ссылок GitHub; модель релизов и assets; консервативный выбор asset без выбора «первого» равнозначного файла; schema-1 валидация `appfleet-manifest.json`; официальный GitHub REST-клиент с `User-Agent`, `ETag`/`If-None-Match`, фильтрацией stable-релизов и понятными rate-limit/HTTP-ошибками; атомарные JSON-хранилища с резервной копией; модели настроек, списка репозиториев и журнала.

**Осталось:** проверка и скачивание файлов, Windows Registry/процессы, EXE/MSI/ZIP-операции, координация операций, полноценный JavaFX-интерфейс, self-update, упаковка Inno Setup, CI и документация выпуска.

**Проверки:** `./gradlew.bat test` успешно (unit-тесты плюс fixture-интеграция HTTP); `./gradlew.bat liveIntegrationTest` успешно выполнила реальную проверку GitHub API и manifest релиза `Pasha-404/sortit` `v1.5.0`; `git diff --check` без замечаний.

## Этап 3 — безопасная установка и обновление

**Реализовано:** потоковое скачивание в изолированную временную папку с отменой, прогрессом, HTTPS/host validation и проверкой свободного места; строгая проверка SHA-256; проверка Authenticode через штатный Windows API; точное read-only обнаружение standard-установки в HKCU без поиска по похожему имени; обнаружение и штатное/явно подтверждённое принудительное завершение только известных процессов; запуск Inno/EXE/MSI через массив `ProcessBuilder`-аргументов; корректная интерпретация MSI-кодов перезагрузки; ZIP-установка с защитой от Zip Slip, проверкой места, заменой через соседнюю staging-папку и откатом.

**Осталось:** оркестрация операции (подтверждения и журнал), главный JavaFX-интерфейс, скачивание манифеста/sha в сценарии, self-update, jlink/jpackage/Inno Setup, CI и итоговые инструкции выпуска.

**Проверки:** `./gradlew.bat test` успешно; добавлены проверки SHA-256, parser Registry, MSI restart code и безопасной ZIP-замены/отката; `git diff --check` без замечаний.

## Этап 4 — сценарии и интерфейс JavaFX

**Реализовано:** главный интерфейс с фиксированной левой панелью, переключателями и версией; табличный список с внутренними вертикальной/горизонтальной прокрутками, fixed header, действиями и контекстным меню; основная командная панель; страница постоянного журнала с раскрытием технических деталей; добавление/проверка/удаление репозитория без удаления программы; диалог выбора файла; отдельное подтверждение операции со сведениями о релизе; отменяемый прогресс; отдельное дополнительное подтверждение принудительного завершения процесса; восстановление запуска ранее работавшего приложения; последовательность self-update до проверки списка с marker-защитой от цикла; автоматический выбор светлой/тёмной темы по настройке Windows при запуске.

**Осталось:** сборка jlink/jpackage app-image, Inno Setup installer со стандартной регистрацией HKCU, генерирование release-manifest/SHA-256, GitHub Actions и завершение README/проверок поставки.

**Проверки:** `./gradlew.bat test liveIntegrationTest` успешно; `./gradlew.bat run` успешно запустила JavaFX-приложение с настоящим module-path, выполнила self-update-проверку перед проверкой списка и была затем остановлена как тестовый процесс; `git diff --check` без замечаний.

## Этап 5 — Windows-поставка и выпуск

**Реализовано:** Gradle-конвейер `test → JAR → проверенный JavaFX JMOD/jlink runtime → jpackage app-image → Inno Setup → optional Authenticode → SHA-256 → manifest`; встроенная Java Runtime без требования Java в Windows; Inno Setup 6 с постоянным AppId, per-user x64-каталогом, безопасным обновлением только известных app-image путей, ярлыками, HKCU-регистрацией AppFleet и безопасным удалением; генерируемые release assets в `dist/release/<version>`; скрипт `scripts/build-release.ps1`; GitHub Actions; README и пример manifest.

**Отклонение ТЗ, подтверждённое компилятором:** `UninstallDisplayVersion` из минимального шаблона стандарта не существует в Inno Setup 6.7.1. Использована существующая `AppVersion`, которая обеспечивает DisplayVersion записи Uninstall Registry; этот факт задокументирован в README.

**Проверки:**

- `./scripts/build-release.ps1 -Version 1.0.0 -RepositoryUrl https://github.com/Pasha-404/AppFleet` успешно сформировал EXE, SHA-256 и manifest;
- standalone app-image успешно запущен со встроенной Runtime;
- silent install `1.0.0` завершился кодом `0`, создал AppFleet HKCU-запись с `Version=1.0.0`, `InstallerType=inno` и главным EXE;
- silent update `1.0.0 → 1.0.1` завершился кодом `0`, обновил версию, сохранил один AppId и одну Uninstall-запись;
- silent uninstall завершился кодом `0` и удалил тестовый программный каталог и ключ AppFleet;
- `./gradlew.bat test`, fixture-интеграция, live-интеграция SortIt и `git diff --check` выполнены успешно.

**Осталось:** исходная реализация, автоматические тесты, сборка, installer и документация завершены. Перед публичной публикацией необходимо передать фактический URL репозитория AppFleet в `-PappfleetRepositoryUrl` и, при наличии сертификата, `-PsignCertificateThumbprint`.
